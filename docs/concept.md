# Concept — SmartDepo

## One-liner
A SaaS that lets any company with physical storage (warehouse, yard, stockroom) build a
**visual** digital map of that space, register every material/product against an exact
location, and let workers find or move anything in seconds via a phone — turning inventory
into a real-time, always-accurate system instead of tribal knowledge.

## The problem
Workers waste time walking around looking for materials because location knowledge lives in
people's heads or on paper, not in a system. That also means stock counts, usage stats, and
accounting numbers are always a step behind reality, since nothing is captured at the moment
it's stored or moved.

## Design principle: visual-first
Both halves of the product are pictures, not forms/lists — that's what makes it fast for
workers, who are the highest-frequency users and often not desk/spreadsheet people:

- **Setting up the space (admin):** the company draws its storage as boxes-in-boxes on a
  canvas — not a form with dropdowns, not a tree of text rows. This is also what keeps
  onboarding simple: drawing a rectangle and naming it is a lower-friction action than filling
  in structured fields.
- **Finding something (worker):** a search result highlights the exact box on that same
  canvas (with a short text path underneath as backup), so the worker recognizes *where* it
  is at a glance instead of parsing a breadcrumb string.

This makes the visual location builder a **core MVP feature**, not a later add-on.

## Core concept: how it works

### 1. Digitize the space (visual builder)
Per facility, the admin gets a canvas. They draw a box for each zone, then drill into a box
to add the next level inside it (rack → shelf → bin), nesting as deep as their real layout
needs — no fixed number of levels, no fixed naming (a company names its own levels: "Yard",
"Aisle", "Rack", whatever fits). This stays simple on purpose: boxes placed on a grid, not
freehand drawing, not to-scale measurements, not a 3D renderer — simplicity over precision.

```
Facility (a warehouse, yard, or site) — the canvas
  └─ Location box (recursive: any name/depth the company chooses)
       └─ ...
            └─ Bin (a leaf box — the place something is physically put)
```

Every leaf box (bin) automatically gets a **QR/barcode label**, generated by the system and
printed/stuck on the physical bin/shelf.

### 2. Register stock
Items/materials/products are registered in a catalog (name, category, unit of measure).
Stock is a link: **item + bin + quantity**. An item can live in multiple bins at once.

Raw/loose materials usually don't have their own scannable barcode (a stack of steel bars, a
pallet of cement) — so the MVP scan target is the **bin**, not the item. Flow:
worker scans the bin's QR → sees/edits what's in it → picks the item from the catalog/search
and sets quantity. This avoids needing to label every individual product.

*(Confirmed direction: per-item barcodes are a valid future layer on top of this — for
products that already carry a manufacturer/company code — without changing the core
bin-first data model. See Phase 2.)*

### 3. Find anything instantly
Worker searches an item by name/SKU in the app → app highlights the exact box(es) on the
visual map where it currently lives, with quantity, plus a text path as backup (e.g. "Yard A
→ Zone 3 → Rack 2 → Bin 14"). This is the core daily value: zero-walk, glance-and-go lookups.

### 4. Every movement is logged
Receiving, picking/consuming, relocating, and adjusting stock are all explicit actions that
write a **movement record** (who, what, from-bin, to-bin, quantity delta, timestamp, reason).
This log is what makes stats and stock levels trustworthy — not a periodic manual count.

### 5. Real-time by construction
Because every state change is a scan-triggered write, "real-time location" isn't a
separate feature to build — it falls out of the data model. The current location of an item
is just the live sum of its stock records.

## Roles
- **Admin** — builds the visual location map, manages users, full reporting access.
- **Manager/Supervisor** — oversees operations, approves adjustments, views reports for
  their facility.
- **Worker** — scans, searches, logs movements from the floor via the visual map. This is the
  daily, high-frequency user — the app must be fast, near-zero-friction, and visual first for
  this role above all.

## MVP scope
- Industry-agnostic, configurable location tree, **built and browsed visually** (boxes on a
  canvas, drill-down by level — not a text tree, not a form-driven setup wizard)
- QR/barcode scanning via phone camera as the tracking method (no RFID hardware for MVP)
- Mobile-first responsive web app — works on a worker's phone and on mounted tablets
- QR code generation for bins (printable labels)
- Item catalog + stock records (item ↔ bin ↔ quantity)
- Search-to-locate flow that highlights the result on the visual map
- Movement logging: receive, relocate, pick/consume, adjust
- Basic dashboards: current stock by item/location, movement history, location occupancy
- Multi-tenant from day one (org-per-company data isolation), multi-user roles
- Quantity + location tracking only — no monetary valuation in MVP

## Explicitly out of scope for MVP (candidate Phase 2+)
- RFID tag support (data model should not preclude adding this later)
- Per-item barcodes as an optional layer on top of bin-scanning (confirmed as a real future
  direction, just not MVP — MVP is bin-scan-first)
- Stock valuation / cost accounting / export to accounting software
- Low-stock/reorder threshold alerts
- To-scale / freehand / 3D floor plans — MVP visual builder is simple nested boxes on a grid
- Offline mode for the scanning app
- Native iOS/Android apps (MVP is a responsive web app)
- Multi-facility cross-warehouse transfers and facility-level analytics rollups
- ERP integrations / API-webhooks
- "Optimal placement" suggestions from movement-frequency analytics
- Pricing/monetization model — deliberately deferred, revisit once MVP shape is solid

## Decisions locked in so far
1. **Name:** SmartDepo
2. **Onboarding:** as simple as possible — achieved through the visual builder itself, not a
   long form/wizard
3. **Pricing model:** deferred to later
4. **Project home:** this folder — `~/Desktop/Depo` — is the project root
5. **Item identity:** bin-scan-first for MVP; per-item barcodes confirmed as a future optional
   layer, not a redesign

## Open questions for next round

- What "as simple as possible" means for the very first box a brand-new company draws —
